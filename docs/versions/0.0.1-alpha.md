# Versao 0.0.1-alpha

Data: 2026-05-15

## Objetivo

Preparar a primeira base alpha do EstudAI com estrutura mais organizada, identidade visual atualizada, inicio da experiencia mobile touch-first, PWA simples, onboarding inicial, base OpenRouter segura e proposta de banco para planos de estudo.

## Alteracoes feitas

- Auditoria inicial criada.
- CSS e JavaScript extraidos de `index.html` e `app.html`.
- Endpoints frontend centralizados em `src/config/api.js`.
- Cliente HTTP frontend centralizado em `src/services/http.js`.
- Visual atualizado para off-white, azul escuro e neutros.
- Emojis visiveis removidos da interface.
- Mobile touch-first iniciado com navegacao inferior, Plano, Rotina e Perfil.
- PWA basico criado com manifest, icone e service worker.
- Configuracao do banco passou a aceitar variaveis de ambiente com fallback local.
- Camada OpenRouter backend criada com endpoints internos e sem chamada direta do navegador ao provedor.
- README, changelog e documentacoes tecnicas criados.
- Design system compartilhado criado em `assets/css/design-system.css`.
- Onboarding local nao obrigatorio adicionado.
- Endpoints internos de IA adicionados para diagnostico e plano.
- Migration incremental `0001_estudai_core_alpha.sql` criada.

## Alteracoes planejadas

- Persistir tarefas/rotina no banco.
- Melhorar icones PWA com PNG em multiplos tamanhos.
- Criar tela offline dedicada.
- Adicionar testes ou verificacoes automatizadas.

## Pendencias

- Nao ha pipeline de build/lint.
- Checklist mobile usa `localStorage`.
- OpenRouter depende de variaveis de ambiente e chave real.
- Migrations foram criadas, mas nao aplicadas automaticamente.
- Service worker ainda nao cobre offline completo.

## Riscos tecnicos

- Projeto ainda e baseado em HTML/JS vanilla com arquivos grandes.
- Algumas preferencias antigas podem manter tema escuro para usuarios existentes.
- Reexecutar `schema.sql` pode duplicar seeds sem controle de migrations.
- A camada de IA ainda usa rate limit simples por sessao; producao precisa limite por usuario/IP.

## Proximos passos

1. Validar fluxo de login e questoes em ambiente local.
2. Persistir onboarding no banco.
3. Exibir diagnostico e plano de estudos na interface.
4. Persistir tarefas mobile no backend.
5. Revisar acessibilidade e navegacao por teclado.
